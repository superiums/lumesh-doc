## 一、前置说明：运行模式

- **Auto (自动模式）**：如未设置，走自动路径：单行走命令优先模式，多行走表达式优先；
- **CFM（命令优先模式）**：开启后，一律走命令优先模式，语法更贴近 bash shell。
- **Normal（表达式模式）**：开启后，一律走表达式优先模式，语法更贴近 编程语言。

切换：行首 `:` 强制 Normal；行首 `>` 强制 CFM。
预设：通过配置文件中设置`LUME_CFM`或cli选项`-m`/`-M`开启/关闭，不设置则为自动模式。

区别：
```bash
# 单个符号
ls               # CFM：单个符号 当命令执行； Normal：单个符号 当询问变量的值执行

# 个别符号：`.` `+` `-` `=`
# CFM: 紧跟字符的符号，将被视为字符串（仅参数位置，命令位置不受影响；紧跟数字后面的，不受影响）
# Normal：紧跟字符的符号，仍然尽可能被识别为运算符号
print a+b        # CFM：输出字符串`a+b`
                 # Normal：输出数学运算结果
```
最简单的应对：**运算符两侧总保持空格**是最好的习惯，这样你就无需关心模式了（虽然Normal模式尽量允许你偷懒）

本指南以下主要按**Normal模式**说明，运算符优先级从低到高排列（同一优先级内注明结合方向）。**CFM模式**会有专门的章节介绍。

## 二、优先级总览

```bash
赋值(=, :=)                     最低，右结合
管道(|) / 重定向
错误处理(?. ?+ ?? ?> ?! ?~ ?:)
Lambda(->)                     右结合
三元(?:)                        右结合
逻辑或(||)
逻辑与(&&)
比较(==, >, <, !=, !==)
命令参数（空格分隔的裸词）
区间(.. ..= ... ...=)           右结合
加减(+ -)
乘除模(* / %)
幂(^)                           右结合
自定义运算符(..xxx, __xxx)
一元前缀(! -)
索引/属性(.)
分组/调用 ( ) [ ]
字面量
```

以下按此顺序逐一说明每一层用户需要注意的写法规则。

## 三、赋值

```bash
x = 1          # 普通赋值
x := expr      # 惰性赋值，expr 不立即求值，读取变量时才求值
x += 1         # 复合赋值（加减乘除都有对应的 += -= *= /= 形式）
```
赋值优先级最低、右结合，`x = a | b` 会先算完管道再赋值。
多个赋值`let x,y = 1`, `x = y = 1`均合法。

---

## 四、管道 `|` 与重定向`>>` `>!`

### 管道
管道支持结构化数据，因此无需像bash一样先`echo data`
```bash
cmd1 | cmd2
data | .upper()        # 管道方法：省略库名，直接调用当前值的方法
0...8 |> print 10 + _  # 循环派发和接收器
data |^ cmd            # pty管道
```
`|` 右侧如果是独立的 `.method()`，会被解析成"管道方法"，语义等价于对左侧结果调用该方法，写法上和链式调用 `x.method()` 是同一套机制，随手写即可。

### 重定向
```bash
data >> file           # 追加输出到文件
data >! file           # 覆盖输出到文件
cmd << file            # 读取文件给命令/函数
```

管道与重定向的优先级**相同**，且遵循**左结合**

## 五、错误处理操作符 `?系列`

这些是接在任意表达式后面的运算符，优先级低，可以包裹前面整段表达式的结果：

```bash
# 成败钩子（成功/失败时）
risky_call() &: next       # 成功时执行函数
risky_call() ?: handler    # 出错时执行函数或返回默认值（惰性求值）

# 流程控制（忽略/终止）
risky_call() ?.        # 忽略错误
risky_call() ?!        # 出错终止（管道中才需要）

# 输出转换
risky_call() ?~        # 执行成败转布尔
risky_call() ?>        # 以错误信息替代返回值

# 打印辅助
risky_call() ?+        # 出错打印到标准输出
risky_call() ??        # 出错打印到标准错误
```

写法要求：符号本身必须整体贴着写（`?.` 中间不能有空格），但操作符与前面的表达式之间可以有空格。也可以直接挂在 `fn` 声明末尾，作为该函数的默认错误处理器：

```bash
cmd_a ?& cmd_b ?: cmd_c    # 与bash的 `&& ||` 语义相同

fn risky(x) {
    ...
} ?: -1
```

**注意**：这里的 `?` 不是三元表达式的 `?`（见下一节），两者靠后面紧跟的字符区分：`?.`/`?+`/`??`/`?>`/`?!`/`?~`/`?:` 是固定的错误处理符号组合；单独的 `?` 后面跟普通表达式才是三元运算符。

## 六、Lambda `->`

```bash
x -> x + 1                # 单参数，无需括号
(x, y) -> x + y             # 多参数，必须加括号
() -> 42                    # 无参数
```
右结合。左侧只能是单个符号或(符号列表)，写默认值/解构会报错。右侧函数体如果是 `{...}` 块直接用，普通表达式会自动包成块。

---

## 七、三元表达式 `? :`

```bash
cond ? true_val : false_val
```
`?` 和 `:` 必须成对出现，右结合。缺少 `:` 分支（只写 `cond ? val`）会报错。

---

## 八、逻辑运算符 `|| &&`

```bash
a || b
a && b
```
`a && b`，即两边用空格分隔。注意lume的这两个符号是纯逻辑运算符，和bash的语义不同。如需命令短路语义，请使用`?&`和`?:`替代。

**注意**：`&&` **不能直接出现在行首**，必须前面有内容（哪怕只是空格分隔的前一个表达式）。

`&` 单独或组合使用（`&+`、`&-`、`&?`、`&.`）不是逻辑运算符，而是命令参数场景下的特殊标记，见第十六节。

---

## 九、比较运算符 `== > < != !== >= <=`

```bash
a == b       #按值比较
a === b      #按类习和值比较
a > b
a != b
```
贴着两侧值写。

`!` 单独出现在独立/行首位置时不是比较运算符的一部分，而是前缀取反，见第十四节；`!=`/`!==` 只有在 `!` 紧贴前一个值的情况下才成立。

## 十、命令参数（裸词调用）

### 10.1 一般参数
```bash
foo x y z        # foo 后面空格分隔的多个字面量/符号，被识别为命令式调用
```
条件：被调用者（`lhs`）必须是符号/变量/字符串/索引/属性之一；如果 `lhs` 已经是数字、列表等字面量，后面又紧跟符号，会直接报语法错误：

```bash
3 foo    # 错误：数字后面不能直接跟符号
foo 3    # 正确
```

### 10.2 扩展参数
- 10.2.1 路径参数 `./` `../` `/` `.` `..`

  其中的`/`因为兼具除法的功能，比较特殊
  + 单独的`/`只有在命令的末尾时才表示路径，如`ls /`是路径，`a / b`是除法
  + `/a`是路径，不是除法，除法后面应空格。

- 10.2.2 家目录扩展 `~`
  `~`会自动扩展为Home目录路径：`ls ~`

- 10.2.3 通配符扩展 `*`
  由于`*`兼具乘法的功能，需注意区分
  
  + 单独的`*`只有在命令的末尾时才是通配符，如`ls *`。而`a * b`是乘法
  + `*.` `*/` `**/`开头的，是通配符。而`a *b`是乘法
  + 路径之中的`*`均为通配符，如`./*`,`../*b`

### 10.3 输出控制与后台运行

命令的尾部支持如下输出控制符：
```bash
# 关闭输出
cmd &-       # 关闭标准输出
cmd &?       # 关闭错误输出
cmd &.       # 关闭所有错误

# 输出重定向
cmd &+       # 错误输出附加到标准输出

# 后台运行
cmd &
```

## 十一、区间运算符 `.. ..= ... ...=`

```bash
a..b        # 不含 b
a..=b       # 含 b
..b         # 省略起点，等价于 _..b
a..         # 省略终点，等价于 a.._
a..b:step   # 带步长
:2          # 独立步长前缀，等价于 _.._:2 (暂不识别..:2的写法)
```
右结合。数字后紧跟 `..` 会被当成"整数字面量 + 区间运算符"，不会误判成小数点：`1..10` 里的 `1` 是完整的整数。

`.` 单独出现时的其它含义（方法调用、管道方法、相对路径）见第十五节，不属于区间运算符。

---

## 十二、加减运算符 `+ -`

### 12.1 加法 `+`

```bash
a + b     # 有空格，加法
a+b       # 贴紧写，加法
a +b      # 命令参数： chmod +x
```
贴紧标识符/数字后面的 `+` 一定是加法（或 `+=`）运算符。

### 12.2 减法 `-`

```bash
a - b     # 两侧都用空格，减法
a-b       # 字符串 c
a - -b    # 减号正确，负号在Normal模式下正确识别为(-b), CFM模式下-b是字符串

# 相似辨析
a -b      # 命令参数： ls -l
a --b     # 命令参数： ls --color
```
**减法应两侧空格**（特例：左侧是非字母可紧凑写：`1-a`）
字母后的紧凑写法`a-b`是连字符，是字符串的一部分。

减号的"负号"含义、以及 `--flag`/裸 `-` 结尾的参数写法，不属于减法运算符，分别见第十四节和第十六节。

---

## 十三、乘除模运算符 `* / %`

```bash
a * b；   a / b；   a % b     # 两侧空格，一定是运算符
a*b      a%b                 # `*`与`%`较为宽松，不空格或单侧空格均可

# 相似辨析
a/b                          # `/`是连字符，整个是字符串
1/b                          # `/`左侧非字符时，不空格也是除号
ls /                         # 结尾的`/`是路径字符串

ls *                         # 末尾的`*`是通配符，`*.xx` `*/` `**/`以及路径之中的`*`均为通配符
```

**除法运算符应两侧空格**（特例：左侧是非字母可紧凑写：`1/a`）。

---

## 十四、幂运算符 `^`

```bash
a ^ b                        # 两侧空格，一定是运算符
a^b                          # 紧凑写法也可以 
a ^b                         # 幂运算

# 相似辨析
a^ b                         # `^`是后缀运算符，让a逃逸变量解析
```

**幂运算符尽量不要作为后缀**（特例：左侧是非字母可以：`1^ a`）。

---

## 十五、一元前缀运算符 `! -`

- **`!expr`**：前缀`!`，表示取反：
  ```bash
  !true         # 逻辑取反得到：false
  ```
- **`-expr`**：前缀`-`，表示取负：
  ```bash
  -5            #负号
  -(a+b)        #负号
  ```

前缀后面不能空格(后面紧跟数字/字母/`(`/`[`/`{`/`.`/`$`)

**对比**：
`-` 作为前缀运算符是（取负）；作为二元运算符是（减法）。

## 十六、索引与属性访问 `.`

```bash
x[i]                 # 索引
x[a..b:step]         # 切片

obj.method()         # 方法调用/链式调用
obj.prop             # 属性访问

a.b().c()            # 链式调用自动合并，不需要手动嵌套
```

`.` 独立出现（前面是空格/行首）时是另一种语义——**管道方法前缀**，用于省略库名直接调用当前值的方法：

```bash
"abc" | .upper()
```
以及路径相关的几种写法和小数：

```bash
./script.sh    # 相对路径（当前目录）
../lib         # 相对路径（父目录）
.              # 单独出现，末尾时表示当前目录路径字符串
..             # 单独出现，末尾时表示父目录路径字符串
.5             # 等价于0.5
```

**要点**：`.method()`（紧贴值后）和 `| .method()`（独立/行首的管道方法）语义相同，只是出现位置不同，随手写即可，不需要刻意区分。

## 十七、其他符号

### 17.1 后缀 `^` 加在纯符号后面，表示"跳过求值"：
```bash
sym^
```

### 17.2 后缀 `！` 加在纯符号后面，表示"执行函数"：
```bash
add! 3 5        # 等价于add(3,5)
```

### 17.3 中缀 `::` 表示"模块调用"：

```bash
mod::func(x)
mod::sub::func(x)
```
左边必须是纯符号，可以多级串接。

## 十八、自定义运算符

### 18.1 自定义后缀运算符

必须以`__`开头，后紧跟任意符号
```bash
let __^ = x -> x.upper().blue()
'lume'__^                                 # 必须紧跟操作对象之后，不能空格
```


### 18.1 自定义二元运算符

必须以`..`开头，后紧跟任意符号
```bash
let ..^ = (x,y) -> x^2 + y^2
2 ..^ 3                                  # 必须两侧空格，区别于不空格的区间运算符
```
二元运算符是具有优先级的，可参与链式二元运算，这是二元运算符比函数方便的地方
- `..+` 开头的自定义运算符，具有与`+`相同的优先级
- `..*` 开头的自定义运算符，具有与`*`相同的优先级
- `..`  其他自定义运算符，具有二元运算符的最高优先级，（比`^`高，比一元运算符低）


## 十九、分组、调用、集合字面量

```bash
a b c          # 命令调用：b和c作为参数传递给命令a
foo(x)         # 函数调用：函数名和括号之间不能有空格
(1, 2)         # 分组/元组表达式
[1, 2, 3]      # List
{a: 1, b: 2}   # Map（有序）
M{a: 1, b: 2}  # 同 Map 的另一种写法
H{a: 1, b: 2}  # HashMap（无序）
S{1, 2, 3}     # BSet（有序）
%{ ... }       # 隔离作用域块，语法同 {}，但具有独立的作用域
```

### 调用

- 命令调用
`cmd a b`
**非严格模式下，symbo会被先查询是否是变量，是则求值**

如果你想传递的是a字面量自身，你可以：
  + 开启严格模式： `lume -s` 或 `sys.set_strict 1`
  + 使用引号：`cmd 'a' 'b'`
  + 使用变量逃逸符号： `cmd a^ b^`

- 函数调用
**函数调用括号必须紧贴函数名**：`foo (1,2)` 中间有空格会被断成独立分组括号，不再是函数调用。

- 内置函数 支持上述3种调用方式
但**当参数中含有lambda、block等复杂语句时，应尽量使用函数调用方式**

- 自定义函数
  + 应使用函数调用方式
  + 如需使用扁平化命令调用方式，应在函数名后加`！`后缀: `foo! 1 2`

### 集合
**集合字面量前缀 `H{`/`M{`/`S{` 只能写在行首/空格后**，不能紧贴在别的字母数字后面。

**Map 字面量规则**：
- 键只能是符号或字符串，不能是数字/表达式。
- 值可以是字面量、变量、符号、List，或另一个 Map/HashMap/BSet 嵌套，等任意**表达式**：
  ```bash
  {a: 1+2}     # 错误
  let x = 1+2
  {a: x}       # 正确：先算好再放入
  ```
- 值可省略，取同名变量：`{a, b}` 等价于 `{a: a, b: b}`。
- **只有一个 key 且不写冒号/逗号时，`{a}` 会被解析成"单条语句的代码块"而非单键 map**，想表达单键 map 必须写 `{a: a}` 或加尾逗号 `{a,}`。更推荐的做法是写`M{a}`。
- `:`前后的空格是可选的

## 二十、字面量

### 20.1 数字

```bash
1_000_000        # _ 千分位分隔，可用在整数/小数任意位置
3.14_159
0b1010_1010      # 二进制
0o755            # 八进制
0xff_80          # 十六进制

50%              # Float：0.5，% 必须贴紧数字
100M             # FileSize：100MB，单位必须贴紧数字

# 相似
192.168.0.1      # IP地址，整体识别为字符串，不拆成数字+.运算符
```
`.5` 合法（省略整数部分的小数）；`3.`（无小数位）非法，需写全 `3.0`。

### 17.2 字符串

```bash
"..."       # 转义字符串
'...'       # 原始字符串
`...`       # 模板字符串
r'...'      # 正则字面量
t'...'      # 时间字面量
s'...'      # 安全字符串（永不被当表达式求值）
b'...'      # 字节字面量
```
前缀字母和引号之间不能有空格。以下协议头开头的整段会直接当字符串，无需引号：`https://`、`http://`、`ftp://`、`ftps://`、`file://`。

### 17.3 特殊值符号

```bash
true false      # 布尔
none            # 空值
_               # 独立使用时是参数占位符（非标识符内部的 _）
```
`_` 用法示例：
```bash
data | cmd _ suffix   # 管道数据占位符
1.._                  # 表示无穷大端点
a[1.._]               # 表示无穷大端点
ls _                  # 命令空白参数占位
```

## 十八、控制流语句

### 18.1 `if`/`while`/`for`/`loop`

主体必须带 `{}`（或 `%{}`）块：

```bash
if cond { a }

for item in list { ... }
for i, item in list { ... }   # 带索引，索引写前面，逗号分隔

while cond { ... }
loop { ... }
```

`else` 例外，可以是 `else if`、块，或单行表达式：
```bash
if cond { a } else if cond2 { b } else { c }
if cond { a } else print("no")
```

- 使用循环时，建议使用`for`，比其他循环更高效。
- 以上语句也可以作为表达式，写在`=`右边。
- 循环如果在赋值环境或管道环境，会自动收集每次循环返回的数据。

### 18.2 `match`

分支之间用**换行**分隔，同一分支内多模式用**逗号**并列：

```bash
match x {
    1, 2, 3 => "small"
    a..b => "range"
    'foo' => "string match"
    g'\d+' => "regex match"
    _ => "default"
}
```

## 十九、声明与语句关键字

```bash
let x = 1
let x, y = 1, 2                # 变量数需与值数一致，或1个值广播给所有变量
let x := expr                  # 惰性赋值
let [a, b, *rest] = list       # 数组解构
let {a, b: renamed} = map      # Map解构，{a}同名简写，{key:newName}重命名
set x = expr                   # 修改父/全局作用域变量
alias name = expr              # 命令别名
export name [= expr]           # 导出变量
del name                       # 删除变量
use "path/to/mod.lm" [as m]    # 模块导入
```
关键字只在行首/空格后生效，用作方法名安全：`regex.match(x, y)` 不会被误判为 `match` 语句。

## 二十、CFM 模式专属：命令参数写法

**CFM（命令优先）模式下**

正确写法：
```bash
git tag v0.0.1        # 参数位置允许 . 号，兼容版本号写法
dd if=/dev/zero       # 参数位置允许 = 号
IFS=''                # 命令名位置的 = 用于变量赋值
ls                    # 命令
```

错误写法：
```bash
print math.max(a)     # `.`不能被识别为方法调用
# 仅影响参数位置的`.`,不影响命令位置的`.`, 直接写`math.max(a)`则正确
let a=1               # `=`不能被识别为赋值，`a=1`整体被作为一个符号
# 仅影响参数位置的`=`,不影响命令位置的`=`, 直接写`a=1`则正确
```

**关键区别**：
- **Normal 模式**：符号被尽量当作运算符处理，单个symbol被当作变量问询。
- **CFM 模式**：某些符号被尽量当作字符串的一部分处理，单个symbol被当作命令执行。

**注意**
当未明确设置模式时，处于自动模式，即单行自动走**CFM模式**，多行走**Normal**模式。

## 二十一、装饰器 `@`

```bash
@deco
fn name(...) { ... }
```
写在表达式开头（行首/空格后）是函数声明的装饰器，可叠加多个，每个占一行。

---

## 二十二、转义与续行

- 字符串内部 `\` 转义下一个字符（含多字节字符按整体跳过）。
- 行尾单独 `\` + 换行是续行符，允许把一条语句写成多行。
- 路径/参数扫描中的 `\` 同样用于转义空格：`ls foo\ bar` 识别为一个整体路径。

---

## 二十三、变量名/命令名可用字符

普通符号除字母数字下划线外，还允许 `~ ? & # $ @ - / \`（兼容路径/命令行参数写法，如 `connman-gtk`）。这些字符在特定位置会被拆成运算符（见前面各节），**纯变量名建议只用字母、数字、下划线，避免歧义**。

## 小结：

1. 从低到高优先级主线：`赋值 < 管道 < 错误处理 < lambda < 三元 < 逻辑或 < 逻辑与 < 比较 < 命令参数 < 区间 < 加减 < 乘除模 < 幂 < 一元 < 索引/属性 < 分组`。
2. 二元运算符尽量两侧空格，无歧义时可以偷懒。
3. 前缀、中缀、后缀运算符空格规则不一样。
4. 遇错时可以尝试行首加`:`切换模式看看。
