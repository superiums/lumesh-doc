# Lume 是什么，值不值得一试？

一句话概括：**Lume（Lumesh）是一门"像 JS 一样写、像 Bash 一样用、像光一样快"的现代 Shell 与脚本语言**，用来替代 Bash，专治各种 Bash 的历史包袱和反直觉设计。

## 亮点（对比 Bash）

| 痛点 | Bash 的问题 | Lume 的方案 |
|---|---|---|
| **语法** | 空格敏感、`[ ]`/`[[ ]]`/`(( ))` 混乱、赋值不能有空格 | 空格可选，`==` 统一比较所有类型，无需括号魔法 |
| **类型系统** | 一切皆字符串，算术要用 `$(( ))`，无浮点、溢出不报错 | 完整类型：整数/浮点/数组/映射/范围/正则/时间/文件大小字面量，运算直接书写 |
| **字符串** | 隐式分割+glob 展开容易"埋雷"，插值嵌套转义地狱 | 三种字符串（单引号原始/双引号转义/反引号模板插值），`StringSafe` 类型防注入 |
| **数据结构** | 数组/关联数组语法繁琐，不支持嵌套访问 | 直观的数组/映射字面量，支持 `select`（类 SQL）和 `get` 点路径访问嵌套结构 |
| **流程控制** | `case` 陷阱多，仅支持通配符匹配 | `match` 支持多值/范围/正则匹配；`if`/`for` 可作为表达式返回值 |
| **函数** | 只有位置参数，返回值只能是 0-255 退出码 | 具名参数、默认值、可变参数、任意返回值、Lambda/闭包/柯里化、装饰器 |
| **作用域** | 变量默认全局污染 | 函数默认隔离作用域，改父级需显式 `set` |
| **管道/子进程** | 管道右侧运行在子 Shell，变量修改丢失；只能传文本流 | 四种管道（标准/位置/分发/PTY），结构化数据（List/Map）直接流动，不启动子进程 |
| **错误处理** | 靠退出码，需手动 `set -euo pipefail` | 编译器级报错提示 + 7 种错误捕获操作符（`?.` `?:` `?+` `??` `?>` `?!` `?~`） |
| **模块化** | `source` 全局命名空间污染，无模块系统 | `use ... as` 模块导入 + 17 个按需加载的内置模块（`list`/`string`/`fs`/`time`/`math`/`regex`/`ui` 等） |
| **性能** | 百万次循环约 2200ms | 约 200ms，快 10 倍以上 |

## 更多特性

- **现代交互体验**：缩写展开、可编程热键/斜杠命令、可编程提示符、语法高亮主题、自动补全，以及**AI 助手**辅助命令补全和智能建议。
- **后台任务自动清理**：主进程退出，后台任务自动跟随退出，无需 `trap`。
- **跨平台**：在任何地方拥有一致体验。
- **兼容日常习惯**：提供 CFM（命令优先模式）方便日常命令行场景，兼容 `include` 简单并入的写法。

## 谁适合用 Lume？

- 受够了 Bash 引号地狱、空格陷阱、隐式变量展开踩坑的人。
- 需要在 Shell 脚本中处理结构化数据（JSON/表格）而不想切换到 Python 的人。
- 想要一个启动快、循环性能高、同时具备现代编程语言特性（Lambda/闭包/装饰器/模式匹配）的日常交互式 Shell 的人。

## 如何上手

提供 `lume`（完整 REPL Shell）和 `lume-se`（轻量脚本执行器）两种形态，支持源码编译、`cargo install`、预编译包或安装脚本等多种安装方式。

总的来说，Lume 的设计哲学是"安全默认、显式优于隐式"，与 Bash "一切皆文本、一切皆命令"的哲学形成鲜明对比——如果你认可"正确的写法也应该是最自然的写法"这一理念，Lume 值得一试。
